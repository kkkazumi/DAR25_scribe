# DAR25_scribe

高齢者インタビュー録音（Human条件・Robot条件）の文字起こしを整え、外注（コエラボ・データグリーン）に渡すまでの前処理プログラム集。

> **個人情報の注意**: 録音・文字起こし・ロボットのログには、参加者の名前や発話内容が含まれます。
> このリポジトリには **プログラム（`*.py`）と `questions.txt` だけ** を入れます（`.gitignore` で除外済み）。
> リモート（GitHub など）へ上げる前に、`git status` で音声や CSV が入っていないことを確認してください。

## 対象

- 面談録音 98 本（49 名 × Human 条件・Robot 条件。`DAR25_001`〜`050`、`017` は欠番）
  - Human：人が質問者。録音条件が悪く、話者分離の精度が低い
  - Robot：ロボット（ぼのちゃん）が質問者。ロボットの発話はログ（`.txt`）で分かる
- 話者が 1 人しか分離できなかった Human の 4 本（007、008、031、047）は、自動処理の対象外（外注へ）
- Robot の 006・018 はログなし、025 はログと録音が合わない（台本との突き合わせで処理）

## 準備

- Python 3.10 以上、`ffmpeg` / `ffprobe`
- ライブラリ：`openai-whisper`（large-v3）、`torch`（GPU 推奨）、`pyannote.audio`（重なり検出）、`matplotlib`（図）
- フォルダの置き方（プロジェクト直下）

| フォルダ・ファイル | 内容 |
|---|---|
| `mp3/` | 元の録音（`DAR25_001_Human.mp3` など） |
| `csv/` | Azure Speech Studio の文字起こし CSV |
| `robot_log/` | ロボットの実行ログ（`DAR25_001*.txt` など。ファイル名に面談番号が入っていること） |
| `questions.txt` | 44 問の台本（1 行 1 問。質問 ID は行番号） |
| `known_names.csv` | 任意。`mp3名,名前` の 2 列。音声・下書きで伏せたい名前を追加する |

## 実行順

各ファイルの冒頭に、詳しい説明と【設定】があります。PyCharm で右クリック → Run。

| 順 | ファイル | 役割 | 主な出力 |
|---|---|---|---|
| 1 | `split_audio.py` | Azure の発話ごとの区切りで、音声を発話単位に分割する | `csv_merged/`、`out_mp3/` |
| 2 | `refine_boundaries.py` | 切れ目の修正（前の発話の末尾が混ざる・途中で切れる）。元の音声から切り直し、最大 5 回繰り返す | `out_refine/`、`csv_merged/`（更新） |
| 3 | `assign_roles.py` | 回答者と質問者を判定。名前を伏せ字にする | `out_roles/` |
| 4 | `transcribe.py` | ローカルの Whisper で全発話を文字起こし（音声は外部に出さない） | `out_transcript/` |
| 5 | `align_questions.py` | 回答者：Whisper にフィラーを戻す。質問者：Whisper のきれいな文。44 問の台本に対応づけて質問 ID を付ける | `out_aligned/` |
| 6 | `detect_overlap.py` | 2 人の同時発話（重なり）を検出（任意） | `out_overlap/` |
| 7 | `parse_robot_log.py` | ロボットのログから、発話と質問番号を取り出す（Robot のみ） | `robot_log_parsed/` |
| 8 | `align_robot_log.py` | Robot のロボット発話をログの文に置き換える。ログと録音が合わない面談は置き換えない | `out_aligned/`（更新）、`robot_log_check/` |
| 9 | `check_quality.py` | 品質を数値化（食い違い度・単語の確信度・重なり率・文の不自然さ） | `out_quality/` |
| 10 | `plot_quality.py` | 品質の分布を図にする（任意） | `out_quality/*.png` |
| 11 | `triage_outsourcing.py` | 外注の振り分けを決める | `out_triage/` |
| 12 | `make_handover_list.py` | 渡す音声（名前は無音）・下書き・送付フォルダを作る | `out_handover/` |
| 13 | `sample_check.py` | ランダムサンプルで品質を確認。聞いて判定し、もう一度実行すると集計する | `out_sample/` |

- 3 は 2 の後、5 は 3・4 の後、8 は 5・7 の後、9 は 8 の後に実行する（依存関係）。
- 各プログラムは、再実行すると前回の出力を再利用するものがある（`transcribe.py`、`make_handover_list.py` の音声）。やり直すときは、該当の出力フォルダを消す。

## 品質の指標

- **食い違い度**：1 つの発話で、Whisper と Azure の文字起こしが食い違った文字の割合（0〜1）。句読点・フィラー・かな漢字の表記ゆれは数えない。正解との誤り率ではなく、2 つの自動文字起こしの不一致を見る目安
- **切れ目が合っている割合**：`refine_boundaries.py` の自動チェックで問題なしだった発話の割合
- **重なり**：2 人が同時に話している割合が 10% 以上の発話

## 外注の振り分け（`triage_outsourcing.py`）

| 依頼先 | 対象 | 渡すもの |
|---|---|---|
| コエラボ（素起こし＋タイムスタンプ） | 話者が 1 人の Human 4 本 | 元の音声まるごと |
| コエラボ（素起こしのみ） | Human：下記の基準のどれかを外れた面談／Robot：「要注意」の面談 | Human：元の音声／Robot：回答者のみの連結音声 |
| データグリーン（校正） | Human：下記の基準をすべて満たす面談／Robot：要注意でない面談 | 回答者のみの連結音声＋下書きテキスト |

- Human の基準（すべて満たすとデータグリーン）：食い違い度の平均 ≤ 0.28、食い違い大（≥ 0.30）の発話 ≤ 33%、切れ目が合っている ≥ 60%、重なりの多い発話 ≤ 30%
- Robot の「要注意」（どれかでコエラボ。回答者の発話だけで計算）：食い違い度の平均 ≥ 0.15、食い違い大 ≥ 25%、切れ目 < 85%、重なり ≥ 10%
- 基準値は、各プログラムの【設定】で変えられる。分布に明確な境目はないので、予算に合わせて調整する
- 質問者の発言は分析に使わない。ロボットの発話はログで分かっているので外注しない

## 個人情報の扱い

- 下書きの名前は「○○」にする。音声の名前の部分は、Whisper の単語の時刻から探して無音にする
- 名前の探し方は完全ではない。送る前に、下書きと「伏せた名前」の列（0 件の面談）を確認する
- `robot_log_parsed/robot_names_PRIVATE.csv` と `known_names.csv` には実名が入る。共有しない
- `out_sample/audio/` の音声は、名前を無音にしていない。外に出さない

## 使わないファイル

## 既知の限界

- Human 条件は録音条件が悪く、切れ目が合っている割合は約 65%（Robot は約 92%）
- 回答者のみの連結音声に、質問者の声が混ざる面談がありうる（Human）。送る前に数本聞いて確認する
- 名前の自動検出は、聞き違いや特殊な言い方では漏れる
